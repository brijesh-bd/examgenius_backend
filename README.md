# ExamGenius AI — Backend API

Node.js + Express REST API for the ExamGenius AI Flutter app. Accounts, tests,
results and saved practice are stored in **MongoDB**; questions are generated by
**Google Gemini** (Google AI Studio). The AI key lives **only here** (`.env`),
never in the app.

## Run it

1. **MongoDB** must be running (Windows: `services.msc` → "MongoDB Server" →
   Start; it is set to start automatically). Data goes to database
   `examgenius` — open it in MongoDB Compass at `mongodb://localhost:27017`.
2. ```bash
   npm install
   npm start          # or: npm run dev  (restarts on file changes)
   npm test           # uses a separate examgenius_test database, wiped each run
   ```

On start the server prints the MongoDB address and the AI mode:

- **LIVE AI** — `GEMINI_API_KEY` set. Models are tried in order
  (`GEMINI_MODEL`, then `GEMINI_FALLBACK_MODELS`) when one is overloaded.
  If all are busy and `AI_FALLBACK_TO_SAMPLES=true`, sample questions are served
  and the app shows them with a "Preview" banner.
- **PREVIEW** — no key: sample questions only.

Test the key without the app:

```bash
npm run try-generate                                    # RRB NTPC · Time & Work · medium · 3
npm run try-generate -- ssc_cgl quant.algebra hard 5 hi # exam, topic, level, count, language
```

### Connecting the app

| Where the app runs | API base URL |
|---|---|
| Android emulator | `http://10.0.2.2:3000/api/v1` (app default) |
| Chrome / Windows | `http://localhost:3000/api/v1` (app default) |
| Physical phone (same Wi-Fi) | `flutter run --dart-define=API_BASE_URL=http://<PC-IP>:3000/api/v1` |

Find `<PC-IP>` with `ipconfig` (IPv4 address). Allow Node.js through Windows
Firewall on private networks when prompted.

## Settings (`.env`)

See `.env.example`. Important: `JWT_SECRET` (keeps logins valid across
restarts), `MONGODB_URI`/`MONGODB_DB`, `GEMINI_API_KEY`, `GEMINI_MODEL`,
`GEMINI_FALLBACK_MODELS`, `AI_TIMEOUT_MS`, `AI_GENERATIONS_PER_HOUR`,
`SECONDS_PER_QUESTION`.

## API (base `/api/v1`)

Auth = header `Authorization: Bearer <token>`. Errors are `{ "error": "message" }`.

| Method | Path | Auth | Body → Response |
|---|---|---|---|
| GET | `/health` | – | `{status, aiMode, models}` |
| POST | `/auth/register` | – | `{name, mobile, email?, password, targetExamId}` → `{token, user}` |
| POST | `/auth/login` | – | `{identifier (email or mobile), password}` → `{token, user}` |
| POST | `/auth/forgot-password` | – | `{identifier}` → `202 {status}` (same reply for unknown accounts; no email/SMS provider yet) |
| GET / PATCH | `/auth/me` | ✔ | → `{user}` / `{targetExamId}` |
| GET | `/exams` | – | `{categories}` |
| GET | `/exams/:examId/syllabus` | – | `{examId, subjects}` |
| GET | `/dashboard/summary` | ✔ | tests taken, accuracy, avg score, recent results (from MongoDB) |
| POST | `/questions/generate` | ✔ | `{examId, topicIds[], difficulty, count, language: en\|hi}` → **session without answers** |
| POST | `/practice/:sessionId/submit` | ✔ | `{answers: {questionId: optionIndex}, timeTakenSeconds, autoSubmitted}` → scored result (idempotent) |
| GET | `/practice/results/:resultId` | ✔ | scored result |
| POST | `/practice/retry` | ✔ | `{resultId, questionIds[]}` → new session (original attempt unchanged) |
| GET / POST | `/practice/saved` | ✔ | list / `{resultId}` → saved set (idempotent) |
| DELETE | `/practice/saved/:id` | ✔ | `204` |

Marking: +1 correct, −0.25 incorrect, 0 unattempted. Accuracy = correct ÷ attempted.

## Data (MongoDB `examgenius`)

| Collection | Contents |
|---|---|
| `users` | profile + bcrypt password hash (unique mobile, unique email) |
| `sessions` | generated tests **with the answer key** — never sent before submit |
| `results` | scored attempts with per-question review and topic stats |
| `saved` | student's saved practice (references a result) |

## Layout

```
src/
  server.js                 entry point (connects MongoDB, starts HTTP on 0.0.0.0)
  app.js                    routes, auth, validation, error handling
  config.js / db.js         .env settings / MongoDB connection + indexes
  data/                     exam catalog, syllabus, sample questions
  services/
    questionGenerator.js    Gemini generator (+ model fallback, samples)
    practiceStore.js        sessions, scoring, results, saved
    userStore.js            users
    examService.js          catalog / syllabus lookups
scripts/try-generate.js     test your Gemini key from the terminal
test/api.test.js            node:test suite (needs MongoDB running)
```

## Before going to production

- `NODE_ENV=production`, a strong `JWT_SECRET`, HTTPS in front of the API.
- Then remove `android:usesCleartextTraffic="true"` from the app's AndroidManifest.
- Add an email/SMS provider for password reset and OTP login.
